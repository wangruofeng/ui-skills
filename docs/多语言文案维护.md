# 中英文文案维护

中文界面使用根路径，英文界面使用 `/en/`。英文源文案与简体中文译文集中保存在 `public/i18n/zh-CN.json`，键为规范化空白后的英文原文，值为中文译文。品牌、技能名、作者账号及代码标识符保留原文。

## 翻译范围

覆盖页面标题与说明、导航、目录简介、资源与设计文档、实践指南、搜索、账号收藏、工具提示、空状态和错误提示。技能 Markdown 正文（`data-original-content`）、代码块、安装命令、URL 和 API 数据标识符不翻译，遵循最初确认的“技能正文保留原文”约定。源数据和导出接口保留稳定英文内容，中文搜索同时匹配英文原文和译文。

本轮公开文案通过智谱 GLM 分批翻译后写入本地版本化词典，并补充人工术语校对。密钥和翻译请求不进入项目代码，站点访问与生产构建无需调用模型。

## 实现与新增文案

- `public/i18n-core.mjs`：纯文本翻译、变量文案和语言链接规则，供构建与浏览器共用。
- `scripts/localize-site.mjs`：构建后生成双语 HTML、本地化元数据与结构化数据，保留技能原文。
- `src/lib/ui-localization.tsx`：React 水合完成后加载词典，在 React 渲染时翻译；静态脚本不改写 React 所有的 DOM，避免水合冲突。
- `public/fork-i18n.js`：增强非 React 动态 DOM 的语言处理。

新增页面文案时，以英文写入源组件并为词典增加对应条目。React 组件使用 `useUiTree()` 处理返回的展示树，或用 `useUiText()` 明确翻译动态字符串。变量文案在共享翻译函数中定义模式；不要翻译 `value`、路由 ID、CSS 类名或提交给 API 的数据。用户生成内容不加入公共词典。

## 本地预览与验证

```sh
npm run build
npm run preview -- --host 127.0.0.1 --port 4325
npm run typecheck
npm test
npm run verify:site
```

英文页面由构建后处理生成，检查完整双语界面应使用构建预览，不能用 `astro dev` 的 `/en/` 作为验收入口。

`verify:site` 包含 `check:i18n`：核对中英文页面文本对应关系、缺失词条及技能原文一致性。漏译列表输出至 `/tmp/ui-skills-missing-translations.json`。专有名词需要明确登记为原文，避免用任意英文兜底掩盖漏译。
